1. Executive Abstract & System Vision

            Refined & Verified
          

          

            The IPL Live Analytics Platform is a cloud-native web application that ingests live Indian Premier League (IPL) match telemetry, processes ball-by-ball events in real time, and delivers actionable insights to cricket fans, data analysts, and franchise team management through interactive dashboards.
          

          

            Rather than displaying static scorecards, the platform executes real-time computational analytics—including AI-driven win probability prediction, player performance indexing, partnership trend tracking, bowling phase efficiency, run-rate forecasting, and head-to-head team comparison. Live match events are streamed through cloud message queues, evaluated in milliseconds, and archived in cloud object storage for historical analysis.
          

        


        

          

            
2. Cloud-Native Microservices Architecture

            High Availability & Low Latency
          

          

            The platform follows a decoupled microservices architecture where independent services manage live data ingestion, real-time AI analytics, role-based user authentication, event notifications, and dashboard visualization.
          

          

            By combining API Gateway, Application Load Balancing, Horizontal Pod Auto-Scaling, Cloud Object Storage, In-Memory & Time-Series Databases, Asynchronous Message Queues, and Real-Time Cloud Monitoring, the system seamlessly supports hundreds of thousands of concurrent users during peak match moments while guaranteeing 99.99% availability and sub-20ms latency.

4. Cloud Project Viva & Architecture Defense Guide

        

          

            
Q1: Why use a Message Queue (Kafka/SQS) instead of direct DB writes?

            
During a boundary or wicket, thousands of telemetry events and millions of fan requests arrive simultaneously. Message queues decouple `live-ingestion-service` from `realtime-analytics-service`, preventing database bottlenecks and guaranteeing zero dropped ball events.

          

          

            
Q2: How does the platform maintain low latency during last-over traffic spikes?

            
Hot match state is served from an in-memory Redis ElastiCache cluster (<5ms read latency), while Kubernetes Horizontal Pod Autoscaler (HPA) automatically scales microservice replicas from 4 to 24 pods behind an Application Load Balancer.

          

          

            
Q3: Why use both Relational/Time-Series DB and Cloud Object Storage?

            
TimescaleDB/PostgreSQL indexes live ball-by-ball time-series queries for the active match, whereas Cloud Object Storage (AWS S3) stores multi-season historical Parquet archives cost-effectively for training the AI Win Probability model.

          

          

            
Q4: How is Role-Based Access Control (RBAC) enforced across microservices?

            
The API Gateway validates OAuth2 JWT tokens issued by `user-auth-service`, injecting role claims (`fan`, `analyst`, `management`, `architect`) so downstream services tailor data granularity automatically.
